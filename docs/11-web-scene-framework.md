# Web 场景加载框架 V1

## 决策状态

**已实现**

- 场景由背景层、氛围层、人物层和 UI 安全区组合，不把角色或按钮烘焙进背景图。
- Day 1 经理办公室场景 ID 为 `tournament_office_day1`；淘汰赛阶段使用各轮次独立场景 ID。
- 登录场景 ID 为 `login_stadium_key_visual`，背景使用唯一现行宣传主视觉 V4；启动时只显示
  场景与登录入口，账号表单打开后通过覆盖层模糊场景。
- 背景通过资源 Manifest 解析 `scene.manager_office.tournament_day1` 的 `desktop` variant；
  本地资源缺失的干净 checkout 自动使用 CSS 经理办公室背景。
- 人物层保留三个御三家锚点和八个六星锚点，分别绑定各自的透明 `standee` 资源，供后续版本复用。
- 首次游玩只开放纱夜路线；后续经理办公室根据当前 `captainId` 渲染纱夜、娜雅或伊蕾娜的
  引导形象与专属台词。页面不提供脱离当前路线的任意看板娘轮换按钮。

实现入口：

| 文件 | 职责 |

## 图层顺序

```text
scene-background-layer    场景背景图或 CSS 临时背景
scene-atmosphere-layer    光影、纹理和不影响交互的氛围效果
scene-character-layer     独立透明立绘与人物锚点
scene-ui-layer            固定在视口内的用户入口、当前队长台词和赛事入口
game-dock                 仅经理办公室显示的全局主导航
```

人物立绘必须保持透明背景，并通过逻辑资源 ID 加载。背景与人物可以独立换版，不要求
重新生成包含 UI 的整张图。

## 大屏安全区

- 桌面场景将左侧最多 48% 宽度保留给经理办公室 UI，右侧用于御三家立绘。
- 游戏外壳、主内容、办公室和场景舞台均固定为一个动态视口高度；`html`、`body` 和
  `#root` 不产生页面级滚动。
- 经理办公室为固定导航预留至少 116px；子系统隐藏全局导航并使用完整安全区。
- 初赛以大屏 Chrome 为主要设计基准；根画布不再强制 `1280×720`，窄窗口最低支持
  320px 且不会横向溢出。经理办公室通过响应式分支重排人物、台词和切换按钮。
- 人物锚点保存桌面横向位置、底部位置和相对场景高度；不在页面组件中硬编码像素坐标。

## 单屏交互规则

- 经理办公室背景覆盖完整视口；16:9 登录宣传图使用 `contain` 完整显示，不因 Chrome
  窗口比例不同而裁切。场景图不放进带外边距和圆角的网页内容容器。
- 不设置横跨画面的顶部状态栏；左上只保留头像式用户入口、昵称和等级提示，展开后
  查看 UID、修改昵称并管理本机会话。底部主导航只在经理办公室显示；进入更衣室、训练、
  赛程或球星卡商店后隐藏，由子系统自己的返回按钮和内部导航接管。
- 首页暂不展示当前目标、俱乐部状态、资料库和下一场快捷按钮；这些信息待剧情和系统
  入口明确后再接入。
- 主界面不通过向下滚动发现功能。更衣室、赛程和球星卡商店均遵循同一外壳，复杂列表
  放进各自场景内的抽屉、分页或局部滚动区域。色彩和表面规范见
  [晴空俱乐部 UI 框架 V1](18-sunny-club-ui-framework.md)。

当前 Day 1 经理办公室场景使用 `tournament-office-day1-v1`：桌面横向图为 1672×941，不包含
人物、文字和 UI。历史窄图可以留作资产记录，但客户端不再解析或加载。V2 使用更明亮、整洁、有希望感的二次元办公室
表达，并保留战术板、旧家具、训练场窗景和足球生活物件。锚点仍只是布局契约；看板娘立绘接入后，必须
再以实际透明边界检查人物间距、裁切、
标题可读性和底部导航避让。

当前场景遵循 Ball Girl 二次元游戏视觉语言参考，并通过新的 `source_version` 保留来源演进。三名御三家立绘使用
`founder-promo-v4-standee-v1`，八名六星使用 `six-star-standee-v1`；两类透明 PNG
都在 Web 数据准备阶段发布到开发服务器。

## 后续资源登记

背景完成后，在统一资源 Manifest 中登记桌面 variant：

```text
scene.manager_office.tournament_day1
  └── desktop   横向场景背景
```

每名御三家使用独立逻辑资源，并提供 `standee` variant。资源文件仍遵循
[资源 Manifest 与本地资产管理 V1](10-asset-management.md)，不直接提交高分辨率母版。
