# 球员养成与技能配置系统 V2

> **历史设计文档。** 实时训练槽、每日补给、常规材料经济、Lv.60 和经验成长均不进入当前
> 杯赛。当前实现见 `docs/20-tournament-numerical-system.md` §训练方向与练度；旧 V3 记录已归档至
> `docs/archive/19-current-training-system-logic.md`。

## 决策状态

**已确认**

- 取消传统 RPG 装备系统，不为球员设置球衣、球鞋、护具、战术芯片等装备槽。
- 球员训练只提升速度、射门、传球、盘带、防守、身体和门将专项等基础能力数值。
- 每名球员拥有一个不可替换的固有天赋，以及由基础星级决定的可配置技能槽。
- 可配置技能分为白、蓝、紫、金、彩五档；低基础星级球员的技能槽更少，可配置的
  技能品质上限也更低。
- 新获得的球员默认只配置与其位置相符的白色、蓝色基础技能。高星球员刚获得时的
  配置同样不完整，后续通过技能收集和替换形成长期养成。
- 重复获得的同名球员用于角色升星，不生成第二个可上场实体。
- 技能成长采用确定性累积；不引入随机主词条、副词条和强化跳点。

**V2 提案，数值待原型校准**

- 角色等级上限、训练槽位、训练时长、各星级槽位结构、技能升品消耗和升星阶段采用
  本文的首版数值框架。
- 当前比赛原型的“基础特性 + 一个招牌技能”迁移为“基础特性 + 固有天赋”；可配置
  技能作为新增比赛层接入。旧 Web 纵切的单一 `skillLevel` 已从当前实现中移除。

**本地试玩原型已实现**

- 存档升级为 V4；按本地测试决策不迁移旧版开发存档，遇到旧结构或损坏数据时创建
  新存档。
- 训练中心开放 2 个训练槽，每次安排 1–5 级；当前每级压缩为 15 秒，消耗训练资金和
  训练笔记，支持离线结算、分段完成与取消后返还未消耗部分。
- 当前提供 18 张代表性技能，覆盖白、蓝、紫、金、彩品质及外场、后卫、中场、前锋、
  门将位置；研习直接获得指定技能卡，不生成随机词条。
- 更衣室已接入 0–5 段重复卡升星、固有天赋展示和按基础星级决定的技能槽；配置时
  校验品质上限、位置、卡片占用和同类技能限制。
- 技能槽采用图形化槽位与选择面板，每项技能以品质色、类别图标和名称首字组成独立
  识别图。红点只提示真实可执行操作：空槽有闲置适配技能，或当前槽存在更高品质且
  未被占用的合法替换技能。
- 训练等级和升星会改变比赛使用的球员能力；配置技能会进入进攻、防守、xG、扑救和
  文字事件，并与固有天赋区分显示。相同阵容、配置与 Seed 仍保持确定性。
- 每日补给按钮当前代表日常任务与商店供给的开发占位入口。正式任务、商店、技能升品、
  第 3 训练槽、训练阶段突破和长周期图谱仍未实现。
- 训练中心已拆为“中心首页 → 基础训练室 / 技能研习库 → 单个技能详情”。首页只负责
  选择培养方向，训练槽、技能清单和研习消耗分别在后续层级展示。

## 为什么取消装备

现代足球运动员在比赛中的实际器材主要是球衣、球鞋、护腿板和门将手套，无法像舰船、
机甲或传统 RPG 角色一样自然承载多件武器和防具。为了复制装备玩法而加入高稀有度
球鞋、手套或虚构芯片，会让长期养成脱离足球语境。

本系统保留装备玩法真正有价值的部分：收集、槽位、替换、品质成长和构筑取舍；载体
从物理装备改为球员掌握的可配置技能。球员的成长由训练决定，球员的比赛用法由
Manager 配置技能决定。

## 随机性取舍

技能养成采用确定性累积作为主干，不复制圣遗物式随机词条。Ball Girl 一套正式阵容
有 11 人，还需要保存多个阵营和阵型方案；如果每名球员再追逐多件随机主词条、副词条
和强化跳点，随机负担会按阵容规模放大，并让玩家难以判断比赛变化来自球员、阵型还是
装备运气。

- 每次日常投入都必须增加某个指定技能的获得或升品进度。
- 允许奖励额外随机出现一张适配技能作为惊喜，但它不能替代目标进度和保底。
- 技能效果、品质上限和升品结果全部确定，不生成同名技能的随机强弱版本。
- 高阶技能通过自选方向、同名残页和进度条收敛，不能出现长期刷取仍无法毕业的情况。
- 长期深度来自 11 人技能覆盖、多套阵容、位置适配和技能组合，而不是垃圾词条库存。

## 角色成长结构

```text
角色等级
  → 训练室提升基础能力

基础星级（3–6 星）
  → 决定技能槽数量和每个槽位的品质上限

固有天赋
  → 保证角色身份，不可卸下或替换

可配置技能
  → 白 / 蓝 / 紫 / 金 / 彩，提供长期收集和构筑

重复角色升星
  → 强化固有天赋与少量职位核心能力
```

角色等级、技能配置和升星都不改变球员的基础星级与固定注册身价。

## 名词与数据边界

| 概念 | 玩家侧名称 | 建议数据字段 | 是否可改变 |
|---|---|---|---|
| 3–6 星能力档位 | 基础星级 / 稀有度 | `base_rarity` | 永久不变 |
| 重复角色养成 | 升星阶段 0–5 | `breakthrough_rank` | 消耗重复卡提升 |
| 基础数值成长 | 角色等级 | `character_level` | 训练室提升 |
| 角色身份机制 | 固有天赋 | `innate_talent_id` | 不可替换 |
| Manager 构筑层 | 配置技能 | `equipped_skill_cards` | 赛前可替换 |
| 技能纵向档位 | 技能品质 | `skill_quality` | 确定性升品 |

不再设置角色自身的统一“技能等级”。技能的纵向进度由白、蓝、紫、金、彩品质表达，
避免同时维护技能等级、技能品质和随机词条三套重复成长。

## 角色等级与训练室

### 角色等级

角色等级是稳定的基础能力成长线，不解锁新的角色身份或技能机制。

**V2 提案**

- 全部角色初始为 1 级，首版统一上限为 60 级，不按基础星级设置不同等级上限。
- 每 10 级为一个训练阶段。阶段突破只消耗训练资金和通用训练材料，不依赖重复卡、
  技能卡或招募代币。
- 升级收益按角色的原始职位能力权重分配。例如中卫优先提高防守、身体和出球，边锋
  优先提高速度、盘带、创造和终结。
- 训练不能改变合法位置，也不能把低基础星级球员训练成同等养成进度下的高星球员。
- 比赛、挂机和任务可以产出训练材料，但不能绕过训练室直接连续提升角色等级。

### 训练室

玩家选择球员并装入训练材料后，训练按现实时间在离线状态继续。材料耗尽或达到目标
等级后停止，不会透支其他资源。

**V2 提案**

- 初始开放 2 个训练槽，俱乐部成长后开放第 3 个槽，不出售永久付费专属槽。
- 每个槽一次只训练一名球员，只产生角色等级和基础能力进度，不训练技能。
- 玩家可以预装约 8–12 小时的训练计划，形成每天一到两次补充材料的节奏。
- 达到预设目标等级后自动停止并保留未消耗材料；更换球员时未消耗材料全部返还。
- 训练完成和材料耗尽分别只发送一次轻量提醒，关闭提醒不会降低收益。

训练室首页必须同时展示训练球员、预计能力变化、剩余时间和材料可维持时间。“一键
补充”只能使用玩家明确允许的材料，不自动消耗技能、升星或招募资源。

## 固有天赋

固有天赋是角色不可替换的核心机制，现有招牌技能迁移到这一层。它保证新获得的高星
球员即使只配置白蓝技能，也能立即表现出独特价值。

例如：

- 边路突破型球员的固有天赋，在一对一成功后提高内切或传中的事件质量。
- 出球中卫的固有天赋，在后场夺回球权后降低第一脚推进失误。
- 节拍器中场的固有天赋，在连续传递后改善下一次机会创造。

固有天赋不占技能槽，不能通过通用技能卡复制给其他球员。它可以通过重复角色升星
获得两次有限强化，但不能成长为与原角色职责无关的另一套机制。

## 可配置技能

### 系统定位

可配置技能承担原装备系统的长期收集与构筑职责。技能卡是“球员掌握的比赛技能”的
游戏化表达，不代表球员在比赛中安装物理装置。玩家在赛前为球员配置技能，比赛开始
后不能临时更换。

一张技能卡在同一套首发方案中只能配置给一名球员。阵容预设需要同时保存技能配置，
切换阵容时一并切换，避免玩家在多套 11 人阵容之间逐张拆装。

### 槽位和品质上限

基础星级同时控制槽位数量和每个槽位的品质上限。V2 推荐使用按槽位限制，而不是允许
六星球员的四个槽全部配置彩色技能：

| 基础星级 | 技能槽数量 | 各槽品质上限 |
|---|---:|---|
| 3 星 | 2 | 蓝 / 紫 |
| 4 星 | 3 | 蓝 / 紫 / 紫 |
| 5 星 | 3 | 紫 / 紫 / 金 |
| 6 星 | 4 | 紫 / 紫 / 金 / 彩 |

低品质技能可以放进高品质槽位，反之不行。技能槽数量和品质上限由基础星级永久决定，
不通过角色升星、付费道具或临时增益突破。

高星球员已经拥有更高基础能力和更强固有天赋，因此高品质槽位必须限制数量。否则
“更高能力 + 更多槽位 + 四张彩色技能 + 更强天赋”会形成多层乘法优势，使低星球员
在阵营补位和专项战术中也失去价值。

### 技能类别

| 类别 | 主要内容 | 示例 |
|---|---|---|
| 技术 | 射门、传球、盘带、抢断、扑救 | 第一脚处理、迎球射门、贴身抢断 |
| 跑位 | 前插、套边、回撤、接应、补位 | 弱侧突袭、肋部接应、回追保护 |
| 战术 | 压迫、出球、控场、反击、防线组织 | 高位封锁、后场接应、节奏转换 |
| 特殊 | 定位球、关键比赛、队长和阵营协同 | 角球落点、逆境专注、三人呼应 |

同一球员原则上每类最多配置一个技能，避免四个槽全部堆叠射门或扑救倍率。每张技能
还必须声明适用位置和比赛阶段；门将技能不能配置给外场球员，边路跑位技能不能绕过
位置适配规则。

### 五档技能品质

| 品质 | 定位 | 机制边界 |
|---|---|---|
| 白 | 教学与最基础能力 | 单一、小幅、无条件效果 |
| 蓝 | 新球员常规起点 | 一个明确条件和一项效果 |
| 紫 | 中期成型技能 | 影响一个完整比赛阶段或事件选择 |
| 金 | 高阶核心技能 | 形成有限的两段事件链 |
| 彩 | 六星长期核心 | 改变特定战术职责，不提供无条件全属性增益 |

高品质技能增加机制深度而不只是扩大百分比。彩色技能仍需明确触发条件和合法概率
边界，不能把低概率事件变成必然结果。

## 新球员的初始技能

新获得的角色默认配置白色、蓝色技能。初始技能应当“效果较弱但方向正确”，不能从
全位置池中随机生成垃圾组合。

例如新获得的六星边锋可以拥有：

```text
固有天赋：边线爆破（固定，不占槽）
白色技能：快速启动
蓝色技能：边路接应
紫色槽：空
金色槽：空
彩色槽：空
```

基础能力和固有天赋保证她立即可用，空缺的高品质槽位则明确展示长期培养空间。初始
配置按角色数据固定并版本化，不因抽取时的随机结果产生同角色强弱差异。

## 技能获取与升品

技能成长采用确定性累积，不使用随机词条。玩家通过日常商店、每日与每周任务、训练
挑战和赛季目标获取指定技能卡、同名残页和通用研习材料。

```text
获得白色 / 蓝色基础技能
  → 收集同名残页与研习材料
  → 确定性提升技能品质
  → 配置到品质上限允许的技能槽
  → 通过比赛报告验证实际作用
```

- 日常商店使用普通比赛货币提供白、蓝技能和通用残页，不消耗招募代币。
- 每日任务提供基础研习材料；每周任务提供紫色技能自选残页。
- 高难训练挑战提供金色技能图谱；彩色技能核心来自赛季和长周期成就。
- 技能来源尽量使用自选方向或目标进度，不建立随机主属性、副属性和强化跳点。
- 已投入技能的升品进度完整继承；不适用技能可以分解为大部分通用研习材料。

白蓝材料在后期仍可向上合成。常规日常与每周供给应足够支持活跃玩家持续推进一个
主技能目标，长期门槛来自高品质图谱和培养选择，而不是技能书基础数量不足。

## 重复角色与升星

第一次获得角色时创建唯一可上场实体；之后每次获得同一角色，增加一枚该角色专属
升星凭证。玩家在更衣室主动确认升星，不自动消耗重复卡。

**V2 提案**

- 每名角色拥有 0–5 个升星阶段；每次升星消耗 1 枚同角色专属凭证。
- 升星主要强化固有天赋，并提供少量职位核心能力与满星外观徽记。
- 升星不增加技能槽，不提高槽位品质上限，不解锁角色等级上限，也不改变固定身价。
- 所选御三家基石的升星凭证由相同层级的主线里程碑提供，离队二人不生成玩家资源。
- 周期玩法可以少量提供通用升星凭证，但日常商店不能无限兑换高星重复卡。

建议的阶段职责：

| 阶段 | 主要收益 |
|---:|---|
| 1 | 小幅职位核心能力 |
| 2 | 固有天赋稳定性小幅提高 |
| 3 | 固有天赋第一次有限机制强化 |
| 4 | 小幅职位核心能力 |
| 5 | 固有天赋第二次有限强化和专属外观徽记 |

## 比赛反馈

文字比赛必须区分三类技能来源：

- `天赋`：角色固有天赋触发。
- `技能`：玩家配置的技能触发。
- `羁绊`：阵营和战术母型效果触发。

赛前阵容页展示每张配置技能影响的比赛阶段。比赛播报说明触发者、条件和结果；赛后
报告分别统计固有天赋与配置技能的触发次数、制造或阻止的机会、xG 和关键贡献。

所有技能随机判定继续使用比赛 Seed。同一角色数据、阵容、技能配置、规则版本和 Seed
必须产生相同结果；技能变更需要批量模拟检查场均进球、阵营胜率、基础星级使用率和
各品质技能使用率。

## 数据与迁移要求

正式长期版本至少需要把以下字段纳入按 UID 隔离的存档；当前 V4 原型先使用角色级
技能数量表和角色默认配置表，便于本地反复重建：

```text
character_progress[character_id]
  character_level / character_exp
  breakthrough_rank / duplicate_tokens

training_room
  slots[] / character_id / target_level
  loaded_materials / started_at / accumulated_progress

skill_inventory[skill_card_instance_id]
  skill_id / quality / upgrade_progress / locked

character_skill_loadouts[loadout_id][character_id]
  equipped_skill_card_ids[]
```

正式上线迁移时，旧 `skillLevel` 不能直接换算成高品质技能。当前本地测试阶段已按
