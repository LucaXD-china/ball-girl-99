# 抽卡系统：阵营卡包、概率与角色演出 V1

> **历史设计文档。** 常规招募货币和购买价格已经退出运行时。当前只使用
> `data/recruitment/tournament-recruitment-v1.json` 的 Day 1 杯赛补强规则。

## 系统定位

**已确认方向，叙事接入待制作**

球星卡商店既提供收集和招募乐趣，也负责把玩家带入球星卡文化。正式主线不以随机十连
作为玩家第一次认识卡片的方式：玩家先在御三家共同经历的比赛后获得首战纪念卡，
理解卡片可以记录球员、赛季和重要时刻，再解锁阵营卡包、稀有度和保底。

球星卡不是脱离比赛的图片奖励。卡片详情应连接角色位置、核心特点、使用建议、值得
观察的球场行为和获得背景；同一名角色可以拥有基础、赛季或纪念版本，但只对应一个
可培养球员实体。跨系统规则见
[足球体验与渐进引导 V1](17-football-discovery-and-guidance.md)。

## 已确认范围

- 球星卡商店提供八个阵营定向卡包，可选择 `1` 抽或 `10` 连抽，使用游戏内招募代币购买；MVP 不接入真实付费。
- 卡包只包含所选阵营的常规球员，御三家等剧情角色不进入卡池。
- 购买成功时立即确定并保存全部结果，关闭页面或中断演出不会重新抽取。
- 玩家沿封口从左向右模拟撕开包装，先看到按最高星级从裂缝中渗出的发光反馈，再展开本包卡数，最后逐张查看卡面。
- 获得的所有卡都进入球员收藏室。重复卡保留可见的持有张数，但同一角色仍只生成一个
  可上场实体；后续养成实现会把额外持有张数安全迁移为该角色的专属升星凭证。

下述常规卡包原型曾使用 `data/recruitment/faction-pack-system-v1.json` 与
`web/src/data/packMarketData.ts`，两者现已归档并退出运行时。赛事版机器可读入口为
`data/recruitment/tournament-recruitment-v1.json`，实现位于
`web/src/data/tournamentRecruitment.ts`，展示流程仍位于 `web/src/pages/PackMarketPage.tsx`。
文档与代码不得各自维护另一份数值。

## 卡池边界与抽取顺序

候选池只来自玩家安全的 `expanded-roster-v1.public.json`，按以下顺序过滤和抽取：

```text
88 人常规运行 roster
→ 移除不可招募角色（当前硬规则：character_id 以 founder_ 开头）
→ 只保留所选阵营
→ 先按概率与保底确定星级
→ 从该阵营同星级候选中等概率选人
→ 更新六星保底、持有张数与首次十连状态
→ 按单抽或十连价格扣款并一次性保存完整结果
→ 才允许开始撕包动画
```

- 御三家是独一无二的剧情角色：序章选择后保留一人，另外两人沿主线作为成长中的对手出现。
- 御三家永不进入常规池、活动池、定向池、兑换池或概率演示，也不产生重复卡、碎片或兑换产出。
- `founder_` 排除在运行时代码中再次执行，即使调用方误把御三家附加到 roster，也不能抽出。
- 若某阵营缺少已抽中星级的候选人，交易必须整体失败，不能降星、换阵营或静默重抽。
- 购买成功时本次结果已经确定并持久化；跳过、关闭页面、刷新或动画中断都不能改变结果。

## 概率与保底原型

**已实现原型，后续按体验数据校准**

| 星级 | 基础概率 |
|---|---:|
| 3 星 | 40% |
| 4 星 | 50% |
| 5 星 | 8% |
| 6 星 | 2% |

该基础分布参考《明日方舟》公开的 `3★40% / 4★50% / 5★8% / 6★2%`，六星软保底参考其[官方概率公示](https://ak.hypergryph.com/news/201904370.html)。Ball Girl 只采用概率曲线，不复制其角色、包装或世界观视觉。

- 每个账号的首次十连至少包含一张 `5` 星或 `6` 星；单抽不消耗这项资格。
- 六星软保底在所有阵营卡包间共享：连续 `50` 抽没有六星后，第 `51` 抽六星率升至 `4%`，以后每抽再加 `2` 个百分点，抽到后回到 `2%`。
- 当六星概率上升时，先从三星概率中让出份额，再从四星概率中让出，五星基础概率保持 `8%`。
- 阵营卡包只改变角色候选范围，不改变星级基础概率。
- 卡包价格 V1 为单抽 `60`、十连 `600` 招募代币；开发模式资源无限，但按钮仍展示正式价格和抽取数量。

## 撕包与翻牌流程

```text
阵营卡包目录 → 选择一个阵营 → 独立卡包详情
→ 查看概率、保底进度与价格 → 选择单抽或十连并锁定结果 → 沿封口从左向右撕开
→ 稀有度发光 → 展开本次卡数 → 逐张翻牌 → 结算总览 → 球星卡商店/更衣室
```

球星卡商店使用一个持续存在的柜台场景，不再在“目录页”和“详情页”之间切换。桌面端左侧
固定八个阵营入口；点击后，中间柜台只展示当前阵营卡包，右侧同步展示该阵营的战术母型、
核心打法、羁绊效果和适配位置。开包演出与结算覆盖当前商店场景，抽取与存档规则不变。

本次卡牌揭晓完毕后，镜头推近柜台桌布并将卡牌依次摊开，不再显示与场景割裂的总结或
提示面板。每张结算卡都可点击放大，查看公开球员信息、六维能力和本次获得状态；关闭详情后
回到同一张桌布上的十连结果，不影响返回球星卡商店或前往更衣室。

场景背景使用 `web/runtime-assets/packs/recruitment-card-shop-counter-v2.webp`：左侧深色货架承载
阵营导航，中间球场线桌布作为卡包展示与开包的视觉锚点，右侧明亮墙面承载半透明阵营档案。
店内陈列通用球星卡包、封装卡盒、评级卡、签名球衣与玻璃展示柜，但不使用真实品牌、球员、
俱乐部或可识别商品设计；当前可购买的阵营卡包和所有文字仍由 Web 动态叠加。

演出反馈由本包最高星级决定：

| 本包最高星级 | 撕开反馈 |
|---|---|
| 3–4 星 | 从锯齿裂缝渗出淡蓝光与冷色微粒 |
| 5 星 | 从锯齿裂缝渗出稳定金光与金色光束 |
| 6 星 | 裂缝过载为强金光和闪白，再向外爆开碎片 |

包装由上层封口、下层包体和内侧卡片三层构成；撕动过程中裂纹横向延伸，上层封口抬起，
卡片边缘逐步露出。品质光只从撕开的缝隙发出，不再使用常驻圆形光晕。鼠标、触屏和触控笔
共用 Pointer Events；键盘用户可用按钮直接完成撕开。拖动阈值只影响演出启动，不影响已保存结果。

## 统一招募视觉语言

三星至六星必须像同一款游戏：横向信号闪、四角阵营色锁定、纵向身份扫描、激活唯一一处
星级标识、显示 `PLAYER SIGNAL LOCKED`。完整时序由
`data/cards/recruit-reveal-language-v1.json` 定义，高星只能在公共段落之后追加效果。

公共视觉边界：

- 暗色径向光场保持干净，不使用背景条纹。
- 人物背后禁止常驻圆环或椭圆法阵；阵营辨识由四角锁定、边缘色光和阵营折线承担。
- 圆形冲击波只允许在六星爆发峰值短暂出现，定格前必须消失。
- 星级只出现一次。完整卡面只激活卡内已有星星；六星透明召唤体才逐颗装入独立星层。
- 姓名、位置、阵营、号码、星级和签名安全区不能被粒子、扫光或冲击波遮挡。

## 跳过、低动态与故障降级

- 跳过只压缩展示，不得跳过保存、改变顺序或重新抽取。
- 六星跳过仍保留一次短促的第六星确认闪光；五星跳过保留金色渐显和已有五星同步激活。
- `prefers-reduced-motion` 取消大幅位移、旋转和高频闪烁，保留星级确认、身份信息和材质色。
- 若运行时分层召唤资产不可用，回退到该角色完整卡面；不得回退到别的角色或占位六星。
- 动效结束后必须能继续逐张查看与进入结算，任何粒子层都不得拦截点击。

## 收藏与重复卡

- 收藏存档记录 `character_id → 持有张数`，因此重复抽到的卡不会丢失。
- 更衣室按角色展示唯一球员实体，并在卡面和档案中展示 `×N` 持有数。
- 基础卡、赛季卡和纪念卡等版本收藏，与“同一基础卡的重复张数”分开表达；引入多版本
  前必须先定义卡片版本存档，不能复用 `×N` 冒充不同版本。
- 新抽到但没有既有培养档案的角色从 `Lv.1 / 技能 Lv.1 / 0 EXP` 开始。
- 每次额外获得同一角色对应 1 枚该角色专属升星凭证；完整养成实现前，V1 继续保存
  原始持有张数，不自动销毁或转换重复卡。
- 后续存档迁移必须保证 `额外持有张数 = 专属升星凭证 + 已消耗的升星阶段`，不能因
  升级存档丢失或重复发放。完整规则见
  [球员养成与技能配置系统 V2](16-player-development-and-skill-loadout.md)。
