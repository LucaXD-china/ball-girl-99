# 对手阵型与专属核心球员扩充方案 V1

> 状态：已实现（30 名专属核心、玩家池隔离、天然位置锁定、卡面与审计已接入）
> 日期：2026-08-28
> 适用范围：《冠军联赛 99 日》15 支杯赛对手
> 关联规则：[杯赛数值子系统 V2](20-tournament-numerical-system.md)

## 1. 目标

在不增加比赛策略复杂度的前提下，让每支对手球队拥有稳定、可辨认的强势位置和核心球员。

本方案不引入球员对位、区域威胁、动态战术适配等新系统，继续沿用现有四阵型克制：

`4-3-3 克 3-5-2 → 4-2-3-1 克 4-3-3 → 4-4-2 克 4-2-3-1 → 3-5-2 克 4-4-2`

设计原则是：

> 阵型决定球队的强弱区域；球员星级强化阵型特点，但不能反转既定克制关系。

## 2. 规则边界

### 2.1 阵型与人员

- 球员强点以球队的**进攻主阵型**为准。
- 防守阵型继续只参与现有的第二条阵型克制轴，不再生成另一套人员强点。
- 每队固定两名对手专属核心；其余高星名额继续由现有共享池和同位置升星补位完成。
- 专属核心必须在表中指定的天然位置首发，不能为了凑星级放到错位位置。
- 同一阵型的球队共享强弱区域，但通过核心的具体位置、属性和技能体现球队差异。

### 2.2 稀有度与抽卡

- 新增卡全部为**对手专属模板**，不进入玩家抽卡池，不改变抽卡概率与保底。
- 4 支剧情对手各配置 `1 名 6★ + 1 名 5★`。
- 11 支普通对手各配置 `2 名 5★`。
- 普通对手进入后期轮次时，额外六星名额由现有共享六星和低星升星补位承担，不为每队预制一名通常无法登场的真六星。
- 真六星继续遵循 16 强 / 八强 / 半决赛 / 决赛 `25% / 50% / 75% / 100%` 的原生六星开放比例。
- 升星卡继续复用原3★/4★通用 chibi 或卡图，只升级卡框、星级和比赛数值；专属核心也可以复用球队通用 chibi。

### 2.3 强弱位置约束

| 进攻主阵型 | 六星优先区域 | 五星填充顺序 | 必须保留的相对弱点 |
|---|---|---|---|
| 4-3-3 | `LW / RW / ST / CM` | 边锋、前锋、中前卫优先，后腰与边后卫最后 | 单后腰、边后卫身后 |
| 4-2-3-1 | `CAM / CDM / LM / RM / ST` | 前腰和双后腰优先，边前卫、前锋其次 | 边后卫、中卫受双前锋压迫 |
| 4-4-2 | `ST / CB / GK` | 双前锋优先，中卫、门将和最多一名中场其次 | 两人中场的中央人数劣势；两翼不能同时成为最高星核心 |
| 3-5-2 | `GK / CB` 优先，名额超过4人后进入中央中场或前锋 | 门将、中卫优先，中央中场和前锋其次，翼卫最后 | `LM / RM` 翼卫不得成为球队最高星核心 |

当某轮高星总名额覆盖全队时，弱点位置可以升到5★，但不能优先获得6★；“弱点”表示相对于核心区域更弱，不要求决赛仍保留3★/4★首发。

### 2.4 羁绊边界

- 当前运行时每支对手固定获得一个与俱乐部传承阵营一致的羁绊，不按随机首发阵营人数叠出多个羁绊。
- 未来新增的30名专属核心只强化本队既有传承，不新增第二层或第二种羁绊。
- 专属核心替换共享球员时，不得改变球队固定羁绊强度；本文件的扩充测算只评估位置与星级变化。

### 3.1 需要同步修订的既有描述

- 苍月竞技的高星核心改为门将与中卫；“肋部创造者”只能作为普通阵容风格，不能再占最高星核心。
- 翡翠联队不再把翼卫列为最高星强点；“往返翼卫”调整为风险来源，核心改为门将与中卫。
- 白曜城只允许一名高星中场，避免两名超巨中场抵消3-5-2的中央人数优势。
- 其余球队的球探文案必须与上表的专属核心、弱点和实际首发一致。

### 4.2 五星：26名

| 位置 | 数量 |
|---|---:|
| GK | 4 |

| CDM | 1 |
| CM | 5 |
| CAM | 4 |

不新增五星 `LB / RB / LM`：这些位置要么属于当前阵型的结构性弱点，要么可以继续由共享池和升星补位承担；本轮扩充只制作能定义球队身份的核心卡。

### 4.3 计算口径

| 口径 | 六星 | 五星 | 说明 |
|---|---:|---:|---|
| 仅保证阵容可生成 | 0 | 0 | 现有共享池和升星补位已经能够补齐每轮配额 |
| 保证15队各有稳定双核心 | **4** | **26** | 本方案采用的内容扩充量，共30名对手专属球员 |
| 给15队各做一名固定六星 | 15 | 15 | 不采用；11支普通对手的六星通常无法在早期轮次登场 |

30名专属核心的推导：

- 4支剧情对手 ×（1名6★ + 1名5★）= 4名6★ + 4名5★；
- 11支普通对手 ×（2名5★）= 22名5★；
- 合计 = **4名6★ + 26名5★ = 30名**。

与“每队新增核心、引擎、弱点球员”共45人的方案相比，本方案不为弱点位置制作新高星卡，直接复用现有3★/4★模板，因此减少15名新增角色。

## 5. 生成顺序

当前对手首发按以下顺序生成：

1. 锁定该球队两名专属核心到指定天然位置。
2. 按阶段配额选择允许登场的原生共享六星。
3. 按阵型强势位置优先级填充剩余原生五星。
4. 缺位或需要降低重复时，从尚未登场的同位置3★/4★模板升星补充。
5. 最后使用普通低星池补齐其余天然位置和替补。

生成器不得为了使用某张高星卡而：

- 把门将放到非门将位置；
- 把3-5-2的翼卫变成球队最高星核心；
- 同时把4-4-2的两翼做成最高星核心；
- 让共享高星覆盖或挤走球队专属核心；
- 把对手专属卡加入玩家招募、卡包或初始阵容。

## 6. 资产与加载约束

- 每名新增核心需要独立角色数据和卡面身份，共30套卡面数据。
- 不要求30套独立chibi；比赛中的人物形象可以继续使用球队通用chibi。
- 如果沿用已有低星角色形象，只生成目标星级卡框和卡面版本，不重复加载一套比赛立绘。
- 图片继续异步解码，并通过现有资产Manifest发布；不得把同一角色的低星、高星大图同时作为比赛页首屏资源。

## 7. 实现与验收清单

### 7.1 数据

- 15支球队均且仅有2名专属核心。
- 专属核心总数严格为30：`6★ = 4`、`5★ = 26`。
- 位置计数与§4一致，所有核心均天然适配指定首发槽位。
- 30名专属核心全部不在玩家抽卡池、初始阵容和招募池中。

### 7.2 阵容生成

- 任意Seed、任意路线、任意轮次均能生成11名不重复首发和天然门将。
- 专属核心在可用阶段稳定首发，不被共享卡或升星卡挤走。
- 共享高星与升星补位遵守§2.3的阵型位置优先级。
- 真六星开放比例仍为`25% / 50% / 75% / 100%`，不因专属卡加入而前置。
- 决赛高星覆盖全队时，结构性弱点最多升为5★，不得优先占用6★。

### 7.3 数值与体验

- 重新测算三条路线的逐轮晋级率、夺冠率和训练方向分布。
- 单支球队核心更换不应使既定阵型克制方向反转。
- 球探页展示的关键球员、强项和弱项必须与实际首发一致。
- 对手高星跨轮重复率不得高于现有升星方案基线。
- 浏览器验证卡面星级、通用chibi复用、首屏请求数量和控制台错误。

## 8. 当前代码落点

当前实现落点：

- `web/src/data/tournamentJourney.ts`：球队核心配置、阵型强势位置、锁定顺序和升星优先级；
- `web/src/data/gameData.ts`及生成数据：30名对手专属模板与玩家池隔离；
- `web/src/data/opponentStories.ts`和球队档案：球探文案与核心位置同步；
- `web/scripts/audit-opponent-promotions.ts`：增加球队核心、位置白名单和星级分布审计；
- `docs/20-tournament-numerical-system.md`：实现并重新校准后同步最终规则与测算结果。

当前 `data/generated/opponent-roster-v1.public.json` 包含 30 名专属核心，每队恰好 2 名；
`generateOpponent` 先锁定天然位置并从分轮高星配额中扣除核心，再使用共享池与同位置升星补位。
`prepare:data` 将对手卡发布为 `opponent-card-art-v2` WebP，玩家招募货架从玩家 roster 推导，
因此不会包含对手专属阵营或角色。数值、路线预算或生成器变化后仍须重跑对手审计与固定 Seed 校准。
