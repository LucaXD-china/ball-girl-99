玩家可选名单 = **路线初始阵容 + 随机补强**。初始阵容由 `TOURNAMENT_STARTER_CHARACTER_IDS`

`6 / 5 / 4` 星。

结算决定是否晋级。（固有天赋与固定携带技能已退出数值模型，只做立绘/文案展示，不影响比分。）

## 初始阵容（固定 18 底座）

每名玩家开局固定持有 18 名底座球员，真源是 `web/src/data/tournamentSquad.ts` 的
`TOURNAMENT_STARTER_CHARACTER_IDS`。它是**常量底座**：对所有玩家完全一致、只贡献均值/下限，
不产生方差；路线的 `60 / 50 / 40` 抽补强在其上叠加随机性（见归因模型「常量底座」）。

组合拳后底座的星级配额为 **3×5★ + 9×4★ + 6×3★（无 6★）**：

| 星级 | 人数 | 作用 |
|---|---:|---|
| 5 星 | 3 | 御三家纱夜（队长）+ 门将 + 中锋锚点 |
| 4 星 | 9 | 主力骨架（CB/CDM/CM/LB/LM/RM/ST 等） |
| 3 星 | 6 | 补位工具人（含第二名门将、边卫、边路） |

- 6★ 不在底座里，只能靠抽卡获得——这是「抽卡爽感」的来源之一。
- 底座保持完整位置覆盖（2 门将 + 后场/中场/锋线各若干），确保能拼出任意阵型的合法 11 人首发。
- 御三家（`founder_` 前缀）不进入补强池，是剧情限定；底座里的纱夜就是那唯一的 5 星御三家。

## Day 1 补强

补强预算随路线递进：纱夜线 `60` 抽、娜雅线 `50` 抽、伊蕾娜线 `40` 抽，可单抽或十连；卡包只从玩家当次选择的阵营出卡，御三家不进入补强池。娜雅线与伊蕾娜线不强制首次十连，可以直接结束补强进入名单注册。

| 星级 | 基础概率 |
|---|---:|
| 3 星 | `40%` |
| 4 星 | `50%` |
| 5 星 | `8%` |
| 6 星 | `2%` |

路线星级上限会屏蔽高于上限的概率，并把被屏蔽概率**等额分给全部仍可抽星级**，不是只流向
4 星或 5 星：

| 路线 | 上限 | 3 星 | 4 星 | 5 星 | 6 星 |
|---|---:|---:|---:|---:|---:|
| 纱夜 | 6★ | `40%` | `50%` | `8%` | `2%` |
| 娜雅 | 5★ | `40.667%` | `50.667%` | `8.667%` | `0%` |
| 伊蕾娜 | 4★ | `45%` | `55%` | `0%` | `0%` |

若软保底使 6 星实时概率上升，超过路线星级上限的实时概率仍按同一规则均摊；因此任意时点概率和
始终为 `100%`。

- 本届第一次十连至少包含一张 5 星或 6 星。
- 顶档跨阵营共享保底：连续未出路线最高可用星级时，第 50 个计入保底的抽取必定为该路线顶档。
- 契约仍记录“50 抽后每抽增加 2%”的软保底，但当前代码先执行第 50 抽硬保底，因此本届运行时
  实际不会进入软保底递增阶段。
- 抽到重复角色只增加持有份数，不生成第二个可同时上场的角色实体。
- 抽卡结果在抽取时确定并写入存档；动画、跳过或关闭展示不会重新投掷。

## 训练方向与练度

### 训练方向

训练中心收束为三个方向：进攻、组织、防守。一次训练课 = 一个方向 + 三名注册球员，消耗
`5` 天。同一名球员本届最多训练 `6` 次（练度 `0/6`），不受单个赛前窗口限制。观察对手（查看
球探报告）同样消耗 `5` 天，与训练在同一备战窗口内二选一；每阶段观察一次、两回合共享情报。
备战窗口按 `5` 天的整数倍铺排（见「淘汰赛与对手强度」），训练/观察后不再自动推进到比赛日，
玩家可随时「直接开赛」跳过剩余天数。

| 方向 | 主属性 +2.4 | 副属性 +1.0 |
|---|---|---|
| 进攻 | 射门 | 速度 |
| 组织 | 传球 | 盘带 |
| 防守 | 防守（门将 → 反应/扑救/站位） | 身体 |

训练只改六项基础属性（及门将三项），不覆盖源 `overall`。属性上限为 `99`；三方向分别主要流入
`终结 / 机会创造 / 防守化解`，并在训练结果中同时反馈分项属性与重新计算后的当前 OVR。

### 星级强度系数

为拉大不同星级之间的基础能力差异、强化抽到高星的感知，杯赛运行时对六维与门将属性应用
星级强度系数（`tournamentSquad.ts` `STAR_ATTRIBUTE_SCALE`）。源 `overall` 保持不变，玩家阵容界面另行派生当前 OVR：

| 星级 | 系数 |
|---|---:|
| 3 星 | `0.85` |
| 4 星 | `0.90` |
| 5 星 | `1.00` |
| 6 星 | `1.10` |

系数只写入「六维 + 门将属性（全部）+ 详细属性」，不覆盖源 `overall`。训练与突破仍是平铺加成、
在系数之后叠加，因此低星练满可「跨一档多」追近高星，
但永远达不到同位置高星未练的上限（对应 doc 01「低星不能追平高星」的硬约束）。

```text
当前 OVR = round(源 Overall × 星级系数 + 主位置职责分训练增量 + floor(突破阶数 / 2))
```

主位置职责分沿用比赛的 `roleScore()` 权重，`CF` 按 `ST` 计算；训练增量比较同一突破阶段下训练前后
的实际属性，因此会正确处理 `99` 封顶。当前 OVR 只用于名单、更衣室、训练结果、赛前平均值以及
玩家主动选择的能力排序/快速填充，不写入存档，也不替换比赛评分、缺省属性或征程评价使用的源值。
抽卡揭晓继续显示「卡面基础 OVR」。

### 练度与满练

- 练度 = 进攻次数 + 组织次数 + 防守次数，`0 ≤ 练度 ≤ 6`。
- 源 `overall` 固定为卡面天赋值，继续用于比赛评分小加成、缺省属性、对手校准与征程评价；当前
  OVR 是可随训练变化的展示/排序派生值，不参与比赛强度。

### 突破

抽到重复卡会自动提升突破阶段，最高 `5` 阶。当前第 `r` 阶要求持有份数满足
`copies - 1 > r`；升阶记录不会减少收藏中的份数，也不需要玩家手动确认。

```text
突破基础点 = 突破阶数 × 0.35
单项属性增量 = 突破基础点 × (0.65 + 原始属性 / 200)
Overall 额外增量 = floor(突破阶数 / 2)
```

突破保留现有加成（含 `overall + floor(rank/2)`），在练度之后叠加。

## 18 人注册与一键首发

玩家从赛事收藏中锁定 `18` 人，之后本届不能更换注册名单。比赛首发只从这 18 人中选择。

一键补完是逐位置贪心算法，不是全局阵容搜索，也不主动优化羁绊：

1. 保留玩家已经放入的位置；门将槽优先填充。
2. 其他空位按“当前候选最难完全适配的位置”优先处理。
3. 每个槽位选择位置能力最高的剩余球员，选中后立即从候选池移除。

```text
位置能力 = 位置职责分 × 位置适配系数
```

阵型不再给球员能力加成：一键补完只按位置职责分 × 位置适配系数选人，不再乘进攻／防守
位置加成系数。

| 目标位置 | 位置职责分 |
|---|---|
| `GK` | 门将扑救值 = `反应×45% + 扑救×35% + 站位×20%`；没有门将属性时为 `Overall × 0.35` |
| `CB` | 防守 50% + 身体 25% + 传球 15% + 速度 10% |
| `LB/RB` | 防守 34% + 速度 26% + 传球 20% + 身体 20% |
| `CDM` | 防守 32% + 传球 28% + 身体 20% + 盘带 10% + 速度 10% |
| `CM` | 传球 34% + 盘带 20% + 防守 16% + 射门 15% + 速度 15% |
| `CAM` | 传球 34% + 盘带 30% + 射门 21% + 速度 15% |
| `LM/RM/LW/RW` | 速度 30% + 盘带 30% + 传球 25% + 射门 15% |
| `ST` | 射门 48% + 速度 20% + 身体 16% + 盘带 16% |

| 位置关系 | 适配系数 |
|---|---:|
| 主位置或副位置完全匹配 | `1.00` |
| 后卫组内客串 | `0.91` |
| 中场组内或边路组内客串 | `0.93` |
| 边路／前腰客串中锋，或中锋／前腰／边卫客串边路 | `0.84` |
| 其他跨位置客串 | `0.72` |
| 门将与非门将互相客串 | `0.20` |

## 赛前准备加成

赛前准备只检查两项：进攻阵型对位克制、防守阵型对位克制。原始加成为：

| 满足项 | 攻击 | 防守 | 每次射门进球概率 |
|---|---:|---:|---:|
| 进攻阵型克制对手 | `+2.0` | `+2.0` | `+0.35%` |
| 进攻阵型被对手克制 | `−2.0` | `−2.0` | `−0.35%` |
| 防守阵型克制对手 | `+2.0` | `+2.0` | `+0.35%` |
| 防守阵型被对手克制 | `−2.0` | `−2.0` | `−0.35%` |

> 克制为**攻防 2×2 交叉、对称（零和）**（`COUNTER_STRENGTH = 2.0`）：
> - 进攻轴：我方进攻阵型 vs 对方防守阵型；
> - 防守轴：我方防守阵型 vs 对方进攻阵型。
> 克制对手 `+2.0`、被对手克制 `−2.0`。克制关系是 4 循环
> （4-3-3 → 3-5-2 → 4-4-2 → 4-2-3-1 → 4-3-3），攻防阵型都沿用同一条循环。
> 推荐克制（`counterFormations`）= 我攻克彼防、我防克彼攻，两个轴各判一次。

> **已移除「职责适配 +3.5」与「防守匹配 +2.5」**：位置不适配已经在 `roleScore = 职责分 ×
> positionFit` 里做过能力打折，再给「≥8 个适配位 +3.5」是重复且无感知的平铺加成（`recommendLineup`
> 自动满足，等于白送）；防守匹配 +2.5 已被 2×2 克制取代。两者删掉后，赛前加成只剩阵型克制一条轴。

> 名单凝聚力（rosterCohesion）已按复赛决策移除：它是「低 Overall 追分」橡皮筋，会把抽卡价值
> 反转（全 3–4★ 队反超全 5–6★ 队），且不进 UI、玩家无法归因。移除后不再重校。

所有赛前效果最终乘本轮阶段系数：16 强 `0.72`、八强 `0.75`、半决赛 `0.92`、决赛 `1.00`。

## 阵型克制参考表（四循环 + 2×2 交叉）

### 1. 克制四循环（谁克谁）

```text
4-3-3 → 3-5-2 → 4-4-2 → 4-2-3-1 → 4-3-3
```

| 克制关系 | 足球逻辑 |
|---|---|
| 4-3-3 克 3-5-2 | 边锋打翼卫身后（3-5-2 的边路空当） |
| 3-5-2 克 4-4-2 | 五中场碾压四中场的中路人数 |
| 4-4-2 克 4-2-3-1 | 双前锋压迫后场出球 + 中场线封锁前腰 |
| 4-2-3-1 克 4-3-3 | 前腰打单后腰身前（4-3-3 的中路空当） |

### 2. 克制矩阵（行克列，· = 不克）

| 行 \ 列 | 4-3-3 | 3-5-2 | 4-4-2 | 4-2-3-1 |
|---|---|---|---|---|
| 4-3-3 | · | 克 | · | · |
| 3-5-2 | · | · | 克 | · |
| 4-4-2 | · | · | · | 克 |
| 4-2-3-1 | 克 | · | · | · |

### 3. 2×2 交叉与最优解公式

比赛按两条轴各判一次克制（对称零和，`COUNTER_STRENGTH = 2.0`）：

- **进攻轴**：我方进攻阵型 vs 对方防守阵型；
- **防守轴**：我方防守阵型 vs 对方进攻阵型。

克制对手 `+2.0`，被对手克制 `−2.0`，两者抵消得净克制。**理论最优解**：

```text
我方进攻 = counterOf(对方防守)
我方防守 = counterOf(对方进攻)    → 净克制 +4.0
```

约束：我方防守必须与进攻阵型「自然兼容」（`compatibleDefenseFormations`）。若理论最优的防守
不兼容，则退回「兼容列表里不被对方进攻克制的那个」，此时防守轴为 0，净克制 +2.0。

## 杯赛单层阵营羁绊

首发中同阵营达到三人即激活一层；同阵营 6 人或 9 人不增加第二、第三层。不同阵营可以同时
激活，每个阵营只影响一个比赛变量。

| 阵营 | 羁绊 | 当前效果 |
|---|---|---:|
| 雾都王庭 | 王庭制空 | 机会创造 `+2.4` |
| 高卢鸢尾 | 疾速突围 | 机会创造 `+2.4` |
| 钢铁引擎 | 压迫齿轮 | 防守化解 `+6.0` |
| 苍蓝堡垒 | 苍蓝反击 | 防守化解 `+6.0` |
| 赤红斗牛 | 连续传控 | 机会创造 `+2.7`（界面显示控球 `+4.5%`，按 `×0.6` 折算） |
| 樱华连结 | 樱华连携 | 机会创造 `+2.7`（同上） |
| 桑巴联盟 | 边线桑巴 | 终结能力 `+5.0`（界面显示进球概率 `+5%`） |
| 潘帕斯银辉 | 银辉定音 | 终结能力 `+5.0`（同上） |
| 大航海团（对手专属） | 远航连携 | 机会创造 `+2.7`（同上） |

四类旧羁绊在 V2 中统一映射到创造、终结、防守三个可感知通道并进入加时；同一 buff 不再同时作为
直接 xG 加成重复计算。点球大战只读取主罚与门将的个人综合值，不受球队通道与羁绊影响。

玩家可同时激活多个不同阵营羁绊。Expert 会比较 `0 / 1 / 2 / 3` 羁绊候选，并用下一场对手的 V2
期望净胜球选择最优首发，不再强制凑满三个羁绊，也不再使用固定 `5.5` 位置能力保护线。

对手不按首发里随机出现的阵营人数叠羁绊，而是固定获得与俱乐部传承阵营一致的一层羁绊；这避免某场
随机叠出多层加成。已经生成的旧存档对手只补该标记，不重抽球员、星级、技能或 Seed。

固定 3,000 Seed 的同阵容配对消融：标准首发的两个羁绊全部关闭，胜率下降 `4.6` 个百分点；强制三
羁绊相对无羁绊提升 `7.2` 个百分点。孤立单羁绊为：创造 `+2.0pp`、防守 `+2.0pp`、传控
`+2.6pp`、终结 `+2.1pp`。因此羁绊已成为可感知的构筑收益，但单层仍不会覆盖阵型与整队练度。

## 90 分钟比赛计算（V2 三通道）

### 球队战斗画像

```text
机会创造 = 按站位加权的创造分
  + 进攻羁绊 + 控球羁绊×0.6

终结能力 = 按站位加权的 (射门×72% + 速度×18% + 盘带×10%)
  + 射门羁绊×100

防守化解 = 按站位加权的 (防守×58% + 身体×25% + 速度×17%)
  + 防守羁绊

门将能力 = 反应×45% + 扑救×35% + 站位×20%
```

创造分随站位变化：中场偏重传球/盘带，边锋和前锋偏重盘带/速度，后场偏重出球；终结权重向中锋、
边锋和前腰倾斜，防守权重向后卫和后腰倾斜。所有分值都乘位置适配系数。阵型本身不平铺加属性，
只通过站位、球员选择与克制关系影响结果。

### 控球与机会数量

```text
主队控球率
  = clamp(50
      + (主队创造 - 客队创造) × 1.2
      + Seed 波动 [-1.5, +1.5),
    28, 72)

单方 90 分钟机会数
  = clamp(round(6.5 + (本方创造 - 对方防守化解) × 0.11 + Seed 波动), 3, 10)
```

双方机会数独立生成，因此一场常规时间总射门不再固定为 13 次；强创造会增加本方机会，强防守会直接
压低对方机会。加时赛采用同一逻辑，单方限制在 `1–4` 次。

### 每次射门进球概率

```text
强弱倍率 = clamp(exp((机会创造 - 对方防守化解) / 18), 0.35, 2.05)
机会质量 xg = clamp((8% + Seed 随机值 × 14%) × 强弱倍率 + 赛前 xg 效果, 1.8%, 62%)

射手 pk 门将：进球概率 = clamp(xg
  + (射手射门 - 对方门将能力) × 0.22%
  + (本队终结 - 对方门将能力) × 0.45%, 2%, 62%)
未进球时扑救判定 = clamp(55% + (门将扑救值 - 射手射门) × 1%, 30%, 85%)
```

射门是否进球，先由团队层面的「机会质量 xg」决定基准，再叠加**射手与门将的个体 pk**：射手
射门即核心六维的「射门」属性（可见、可训练），门将扑救值 = 反应×45% + 扑救×35% + 站位×20%。
未进球时再按门将优势判断是扑出还是射偏。内部字段仍名为 `xg`，此时它表示「终结前的机会质量」，
实际进球会随射手射门与门将扑救的差距在 xg 上下浮动，不再等于 xg 本身。

### 固有天赋与固定技能

- 固有天赋与高星固定携带技能已退出数值模型：不改变 xg、比分、胜负，也不计入球员评分与赛事 MVP。
- 比赛过程仍按 `36%`（固定技能）→ `52%`（固有天赋）判定触发一次「技能发动」，仅用于文字直播与立绘高光，展示身份名 + 风味文案，并把次数记为「X 次技能」的统计展示。
- 配置技能库存、装配和等级不会改变杯赛结果，也不进入展示触发。

### 赛后归因总结

每场赛后（`MatchResultView`）在结算报告后追加「为什么是这个结果」四行 + 运气行，由
`web/src/data/matchReport.ts` 的 `buildMatchAttribution` 确定性解析（不重跑模拟）得出：

- 四行 = 阵型克制 / 球员强度（练级 + 抽卡合并）/ 阵容适配 / 羁绊；
- 玩家侧只显示「影响程度（明显 / 略微 / 没有）+ 一句优化方向」，不显示任何数值；
- 决赛夺冠不跳过四行：夺冠后玩家同样需要知道「是怎么赢的」，四行归因照常展示。

## 淘汰赛与对手强度

16 强、八强和半决赛采用两回合总比分，不使用客场进球规则；决赛为单场。总比分或决赛
90 分钟战平后进入决战准备，再以常规比赛机会逻辑生成 5 次加时机会；仍平则进行五轮点球
和突然死亡。点球主罚综合值为 `点球×62% + 冷静×18% + 终结×12% + 射门力量×8%`，
门将综合值为 `反应×45% + 扑救×35% + 站位×20%`（即门将扑救值，与开放射门一致）。单次命中率以 `74%` 为中心，主罚和
门将综合值每偏离基准 1 点分别调整 `0.25` 个百分点，并限制在 `50%–92%`。

每轮对手从未被玩家注册的公开角色模板中生成合法首发，并按当轮星级阶梯补齐 5★/6★ 名额。
对手不再人为校准 Overall：球员直接使用模板原生能力，并对六维/门将属性应用与玩家一致的
`STAR_ATTRIBUTE_SCALE`（对称星级系数，见 `tournamentSquad.ts` `applyTournamentProgress`）。

## Expert 理论最优策略与批量校准

数值验收只定义一个 `expert` 模型；不再估计、细分或约束普通玩家晋级率。纱夜线对非 expert 玩家
保留随机通关可能，但该概率不进入实现门槛。

### 理论最优抽卡策略

抽卡的星级概率与阵营无关，所以“追某阵营提高高星率”没有意义。每包的最优选择是：在当前收藏、
路线星级上限和保底进度下，选择**期望 18 人名单边际收益最高**的阵营：

```text
候选角色边际收益
  = 进入预计 18 人名单后的职责潜力提升
  + 重复卡带来的下一阶突破提升
  + 首次凑到该阵营 3 人时，对应羁绊的实际战斗通道收益

阵营期望收益
  = Σ星级 [当前实时星级概率 × 该阵营该星级角色的平均边际收益]

本包选择 = argmax(阵营期望收益)
```

实现中的职责潜力取球员在全部合法阵型槽位里的最高位置能力；预计名单固定先保留两名天然门将，再取
其余最高值至 18 人。羁绊跨过 3 人门槛时按实际映射计入代理值：创造 `2.4 / 2.7`、终结 `5.0`、
防守 `6.0`；对手专属的大航海团不进入玩家抽卡候选。该策略每包重新计算，不能简化成
“永远抽队长阵营”或“永远补人数最少阵营”；它是一阶前瞻的理论最优策略，不读取未来随机数。

重复卡自动突破，不存在囤卡收益，因此抽到后立即突破是严格占优策略。模拟器按实际预算完整经过
`60 / 50 / 40` 抽，不在预算之外注入高星球员。

### 理论最优训练策略

每个可用训练槽都应使用；跳过训练不会换来其他战斗资源，因此没有保留天数的正收益。对下一场已知
对手，遍历三个方向，并在该方向下选择边际收益最大的 3 名未满练球员。目标函数是 V2 比赛公式的
确定性期望净胜球代理：

```text
单方期望进球 = 预计机会数 × 预计单次进球概率
训练目标 = argmax(我方期望进球 - 对方期望进球)
```

组织训练通过创造提高机会数与 xG；进攻训练通过射门/终结提高转化率；防守训练同时压低对方机会数与
xG，门将防守训练还会提高门将能力。最优方向会随当前首发、属性上限和下一场对手变化，不存在全程固定
只练一个方向的最优解。实现会逐课重算并记录 `attack / playmaking / defense` 课次用于复核。

Expert 同时使用公开球探信息选择克制阵型；首发从一键阵容与 `1 / 2 / 3` 羁绊候选中，选择对下一场
对手期望净胜球最高者。羁绊不是强制指标：若换人的位置损失大于羁绊收益，理论最优解仍可选择零羁绊。

### 归因基线（消融）

逐因素测量杯赛结果的影响占比（净胜率差 ΔP）与比赛随机噪声，用于约束「玩家操作 vs 不可控」的
比例。脚本真源是 `web/scripts/ablate-attribution.ts`；度量口径与消融方式见归因模型历史文档。
当前脚本已经迁移到 V2 三通道公式；下表是描述性快照，不作为提高对手难度的触发器。

```bash
cd web
npm run simulate:ablation -- --seeds 2000 --stage round_of_16
```

V2 当前实测（羁绊部分 `--seeds 3000`；其余端点由同版脚本输出）：

| 因素 | 端点 A → B | 当前 ΔP / 分布 | 当前解读 |
|---|---|---|---|
| 养成（练级） | 满练(练度6) → 0练（标准抽卡后） | `48.5pp`（`67.8% → 19.3%`） | 仍是最大可控变量 |
| 抽卡增量 | 好抽(P90) → 差抽(P10) | `10.1pp` | 有影响但不决定冠军 |
| 阵容阵型 | 克制 → 默认 | `26.3pp` | 四阵型克制保持核心地位 |
| 对手风格 | 同强度更换对手题型 | 胜率极差 `6.0pp` | 可感知但弱于阵型克制 |
| 阵营羁绊 | 标准两羁绊 → 全关闭 | `4.6pp` | 构筑收益清晰但不压过阵型 |
| 比赛随机 | 固定阵容跨比赛 Seed | 胜 `10.2%` / 平 `21.0%` / 负 `68.8%`，净胜球 `σ=1.40` | 单场可波动，长期不主导构筑收益 |

> 单因素 ΔP 使用各自端点，不能直接相加解释一场比赛；阵型、训练、抽卡和羁绊会通过首发与三通道互相
> 作用。当前结论是玩家操作仍显著高于羁绊和随机噪声，不存在“夺冠全靠比赛随机”的结构。

## 数值改动验收清单

修改抽卡、成长、阵型、羁绊、技能、对手或比赛公式时，至少完成：

1. 说明改动落在链条的哪个环节，以及预期改变哪个可观测指标。
2. 使用相同 Seed 对改动前后做配对比较，不用一届比赛判断强弱。
3. 查看 expert 的止步分布、条件晋级率、场均比分、射门、预期进球、控球与三类训练课次。
4. 检查纱夜 / 娜雅 / 伊蕾娜的相对难度仍为易 / 中 / 挑战；旧 `30% / 15% / 5%` 上限只作历史比较，
   不以提高对手星级的方式追回上限，也不建立普通玩家门槛。
5. 运行 `npm test`、`npm run build` 和 `git diff --check`。
6. 同步本文的当前参数和校准快照；不要用历史 Python V4 结果替代当前 Web 全流程结果。
