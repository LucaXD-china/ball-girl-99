> **历史设计文档。** 本文保留旧单场与社区赛原型说明；当前运行时只有七场《冠军联赛99日》
> 赛程。当前一键补完、比赛推进、评分和加时／点球规则以
> [文字比赛与技能系统](04-match-and-skills.md)及赛事文档为准。

## 决策状态

**已实现**

- 赛程是固定底部导航中的第四个开放入口，当前提供一场可重复挑战的季前社区赛。
- 单局比赛固定采用“查看对手 → 进攻阵型 → 防守阵型 → 11 人名单 → 比赛 → 赛后结算”
  六步流程。对手情报只在第一步集中展示，不持续占用后续阵型和名单页面的右侧空间。
- 第一步页面标题使用“赛前备战”。除预计攻防阵型与战术提示外，还使用与我方选人一致的
  球场和立绘槽展示对手预测首发的 11 个位置。双方已入选球员槽只显示一个最终加权能力角标，
  数值结合所在位置、进攻阵型加成和无球阵型加成计算；角标悬浮在卡片右上角，不挤占姓名、
  位置和加成说明。页面展示的预测首发应直接传入比赛，
  不允许开赛后重新生成另一套对手名单。
- 进攻与防守阵型各自占用独立页面。阵型列表固定在左侧，玩家可以自由切换；右侧只渲染
  当前选中的一套阵型大图、位置人数、逐位置加成和文字说明。确认当前阵型后才进入下一步，
  不在一个页面同时铺开多套阵型的完整信息。
- 进攻阵型决定 11 个选人槽位及有球阶段加成；防守阵型作用于同一批首发在无球阶段
  的能力，不维护第二套名单。每张攻防阵型卡都使用球场站位图展示 11 个位置、逐位置
  加成与门将/后卫/中场/前锋人数，并配套结构特点和主要风险说明。
- 每种进攻阵型只展示可由当前 11 人自然切换的防守阵型；不适配项不显示。玩家改变
  进攻阵型后，如果原防守阵型不再适配，系统自动回到该进攻阵型的首个合法选项。
- 阵型加成按百分比计入对应比赛阶段的球员能力，不修改公开角色数据中的原始
  Overall，也不改变固定注册身价。
- 每个位置可以从当前开发 Box 的已持有球员中选择；空位显示宽肩比例、带轮廓层次的深色半身剪影，已选择
  位置显示球员卡面上半身、短名、等级和阵型加成。正式主线接入后，11 人页面只在
  玩家完成渐进阵容与职业准入时开放。
- 阵型图和名单球场统一采用“本方门将在下、前锋在上、向上进攻”的阅读方向；上下两端
  都要画出禁区，中线必须横向贯穿球场，并用进攻箭头消除方向歧义。名单页优先保证球场
  和球员槽可读，桌面球员名称不得再使用小于 `10px` 的主文字。
- 名单页实时统计已选球员的阵营。每三名同阵营球员激活一层羁绊；已经选入但不足三人的
  阵营使用灰色卡片显示 `1/3` 或 `2/3`，已激活阵营显示层数，并继续展示下一层进度。
- “一键补完名单”按照位置适配、当前位置能力、进攻加成和防守加成，只填入当前空位，
  不移动或替换玩家已经选择的位置，且不重复使用球员。
- 位置选择器允许点击已经上场的球员。确认后该球员移动到当前目标位置，她原来所在的
  位置立即变为空位，不进行隐式互换。
- 比赛开始后全自动播放确定性的文字事件；除射门、扑救、进球和技能外，普通事件按球权
  推进链组织：每次机会由本方后场一路传到紧邻射手的传球者，再完成射门，让球的转移顺序
  在空间上连贯，并确保每名首发至少进入一次过程记录。推进链只用于解说与场上动画，
  不改变比分、xG 或技能触发。同一首发、攻防阵型和 Seed 得到相同结果。
  比赛期间没有体力、替补、自动换人或临场手动操作。
- 固有天赋与玩家配置技能使用不同触发来源并显示球员卡面立绘、中文短名、技能名和
  比赛效果；配置技能会直接进入进攻、防守、xG 或扑救计算。用户主动点击开赛后，
  通过 Web Audio 播放开场、进球、技能和终场提示音，可随时静音。
- 赛后展示最终比分、控球、射门、xG、技能触发、攻防阶段能力、双方 22 名首发的完整
  球员评分与 MVP 卡面；评分表允许滚动查看，不再只截取前 8 名。
- 比赛只读取公开 88 人数据、公开技能文案和 Web 卡面预览；不得暴露能力原型、现实
  国籍、现实俱乐部或来源三元组。

**原型数值，待校准**

- 进攻阵型位置加成为 `0%–10%`，只进入控球、推进、创造与终结计算。
- 防守阵型位置加成为 `2%–10%`，只进入压迫、盯防、解围与扑救计算。
- 浏览器纵切复用控球、机会、xG、技能、扑救和评分概念；正式数值收敛时应让 Web 与
  版本化契约保持一致。

**待定**

- 正式赛程关卡、对手成长、奖励、消耗与赛后存档结构。
- 阵营羁绊与战术母型软克制在 Web 报告中的完整拆解方式。
- 攻防阵型是否允许保存为多套预设，以及未来对手情报是否需要增加可信度和动态变化。

## 标准阵型引导

**阵型图与基础介绍已接入，比赛反馈待继续制作**

十一人模式负责正式介绍标准位置和阵型。每套阵型除名称、位置槽和百分比外，还必须
说明球队如何推进、如何创造机会，以及丢球后由哪些位置保护危险区域。位置加成使用
足球语义解释，例如边锋获得更大的边路一对一空间、双后腰共同保护中卫身前区域，
不能只显示 `+10%`。

一键推荐需要在现有自动填入基础上给出少量关键理由，包括最佳门将、主位置完全适配、
阵型关键职责或当前 Box 中的替代选择。赛后报告增加一条与玩家本场选择直接相关的
“本场足球发现”，并允许展开位置、阵型、技能和 xG 的详细影响。基础说明允许跳过，
不会阻止熟悉足球的玩家直接进入完整构筑。

三人至十一人的完整认知顺序见
[足球体验与渐进引导 V1](17-football-discovery-and-guidance.md)。

## 四种进攻阵型

| 阵型 | 主要加成位置 | 定位 |
|---|---|---|
| `4-3-3` | 边锋 `+10%`、中锋 `+7%`、中场 `+5%` | 拉开宽度与边路压迫 |
| `4-2-3-1` | 前腰 `+10%`、边中场 `+7%`、双后腰 `+5%` | 双轴推进与前腰串联 |
| `4-4-2` | 双中锋 `+9%`、边中场 `+8%`、中场 `+4%` | 传中、争顶与二点进攻 |
| `3-5-2` | 前腰/中前卫 `+8%`、双前锋 `+8%`、翼卫 `+7%` | 中路合围与翼卫推进 |

## 四种防守阵型

| 阵型 | 主要加成位置 | 定位 |
|---|---|---|
| `4-3-3` | 防守中场 `+6%`、中卫 `+5%`、边锋压迫 `+7%` | 前场压迫与快速反抢 |
| `4-2-3-1` | 双后腰 `+10%`、中卫 `+7%`、边后卫 `+5%` | 中路保护与转换防守 |
| `4-4-2` | 中卫/中场 `+8%`、边后卫 `+7%`、前锋 `+5%` | 两条紧凑防线 |
| `5-3-2` | 中卫 `+10%`、防守中场/翼卫 `+8%`、门将 `+5%` | `3-5-2` 的翼卫回落形态；禁区保护与人数合围 |

## 攻防阵型适配

| 进攻阵型 | 可选防守阵型 | 转换依据 |
|---|---|---|
| `4-3-3` | `4-3-3`、`4-4-2` | 保持三前锋压迫，或由一名中场前提、边锋回收形成两条四人线 |
| `4-2-3-1` | `4-2-3-1`、`4-4-2` | 保持双后腰保护，或让前腰前提、边前卫回收形成 `4-4-2` |
| `4-4-2` | `4-4-2`、`4-2-3-1` | 保持双线紧凑，或由一名前锋回撤承担前腰连接 |
| `3-5-2` | `5-3-2`、`4-4-2` | 翼卫回落形成五后卫，或一侧翼卫与边中卫重组四后卫、另一侧回到中场 |

该表是当前 Web 单局流程的合法切换契约，不是阵型强弱或固定克制表。以后若增加
`5-3-2`、`4-1-4-1` 等无球专用结构，应先明确同一批首发如何换位，再扩展可选项。

## 页面流程

```text
赛程首页
  → 第 1 步：赛前备战；查看对手预计攻防结构、11 人预测首发和能力值
  → 第 2 步：从左侧自由选择进攻阵型，右侧查看当前阵型大图与明细
  → 第 3 步：从左侧选择适配的防守阵型（隐藏不适配项，单图查看）
  → 第 4 步：逐位置选人 / 一键配置 11 人 + 完整性检查
  → 第 5 步：全自动文字比赛 + 技能立绘 + 提示音
  → 第 6 步：最终比分 + 结算报告 + MVP 立绘
  → 返回调整阵容 / 使用同一阵容重赛
```

页头显示“对手 → 进攻 → 防守 → 名单 → 比赛 → 结算”六段进度。名单页返回键退回防守
阵型，防守阵型页退回进攻阵型，进攻阵型页退回对手情报；只有对手情报页的返回键会离开
赛程系统。
