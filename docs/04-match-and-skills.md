# 文字比赛与技能系统

本文记录当前《冠军联赛99日》杯赛 Web 运行时的一键补完、比赛模拟、事件播放和淘汰赛
结算规则。比赛在浏览器本地由 TypeScript `simulateMatch()` 执行。

抽卡、成长、位置能力、赛前加成、阵营羁绊、比赛概率、对手强度、结局分布和批量校准的当前
数值统一见[杯赛数值子系统 V1](20-tournament-numerical-system.md)。本文只保留比赛流程、事件
播放和运行边界，避免同一参数在多份文档重复维护。

规则冲突时，以下述为准：当前杯赛的固有天赋与固定携带技能只做立绘/文案展示，不读取配置技能库存、装配或等级改变赛果。

## 当前杯赛 Web 运行边界

**已实现**

- 比赛在浏览器本地、开赛按钮被点击时一次性生成完整结果，并立即写入当前账号的杯赛存档。
- 文字直播只是按顺序播放已经生成的事件；播放速度不参与模拟，也不会改变最终比分。
- 同一阵容、等级、攻防阵型、对手和 `fixtureSeed` 得到同一结果。
- 当前只有 11v11 杯赛比赛；三人训练赛、5v5、实时 PVP 和服务端模拟不在本届运行时中。
- 比赛期间没有体力、替补、自动换人、临场战术或手动操作。

## 一键补完 11 人名单

### 候选范围与保留规则

“一键补完名单”调用 `completeLineup()`，候选池只包含本届已经锁定的 18 名注册球员。
球员进入候选池前已经应用当前杯赛等级和突破带来的属性变化。

- 已经手动放入的位置保持不变，只填充空位。
- 已使用球员从候选池排除，不会重复进入两个位置。
- 进攻阵型改变时会按新阵型清空名单；只改变防守阵型不会清空名单。
- 候选不足时允许保留空位，但未填满 11 人不能开赛。

### 填充顺序

算法是逐位置贪心，不是全局最优阵容搜索：

1. 门将位置始终最先填充。
2. 其他空位按当前注册名单能够达到的最高位置适配度从低到高处理。
3. 适配度相同时保持进攻阵型中的槽位定义顺序。
4. 每填入一名球员后立即从剩余候选中移除，再处理下一个位置。

当前 18 人注册名单通常能为每个标准位置提供完全适配球员，因此除门将外，多数情况下表现为
按阵型槽位定义顺序依次填充。

### 位置能力

每个空位选择“该位置能力（位置职责分 × 位置适配系数）”最高的剩余球员。职责权重与位置适配
系数统一见[杯赛数值子系统：18 人注册与一键首发](20-tournament-numerical-system.md#18-人注册与一键首发)。

当前一键补完不优化阵营羁绊、技能组合、稀有度、对手特点或全队总能力，也不会为了提高整体
结果而回溯交换已经填入的球员。

## 开赛输入与赛前效果

开赛要求首发已经填满 11 人且日期到达比赛日。模拟器读取：

- 双方 11 人首发及训练后的公开属性；
- 双方进攻阵型和防守阵型；
- 杯赛预先生成的对手首发；
- 当前关卡的固定 `fixtureSeed`；
- 我方针对本轮对手计算的赛前效果。

赛前效果检查推荐攻防阵型和位置职责适配，再叠加当前杯赛的单层阵营羁绊。具体加成、阶段缩放、
凝聚力、八阵营效果和四轮对手强度统一见[杯赛数值子系统](20-tournament-numerical-system.md#赛前准备加成)。

## 90 分钟比赛生成

### 双方能力与控球

双方分别汇总进攻与防守能力；控球率再决定 13 次射门更可能属于哪一方。球队能力、控球和
射门归属公式统一见[杯赛数值子系统：90 分钟比赛计算](20-tournament-numerical-system.md#90-分钟比赛计算)。

### 固定事件结构

每场固定生成 13 次射门机会，分钟为：

```text
7, 13, 19, 27, 34, 41, 49, 56, 63, 70, 77, 84, 89
```

同时生成：

- 0 分钟开场事件；
- 每次机会前，按「后场 → 前场」的球权推进链生成 2 条普通参与事件（更靠后的接应点
  与紧邻射手的传球者），中场休息前共 22 条；若控球偏斜导致个别首发未进入普通事件，
  补录参与记录并均匀打散到全场（6'–86'），保证每名首发至少进入一次过程记录；
- 45 分钟半场事件；
- 90 分钟终场事件。

因此当前完整 90 分钟通常包含 38–44 条事件。普通事件按位置显示组织推进、中场对抗或
攻守转换，用于让球的转移顺序在空间上连贯（从本方后场一路推进到射门）；它们与射门
机会共用一条独立的随机流，只影响解说归属与场上动画，不会改变控球、xG、技能或进球结果。

### 单次射门机会

每次机会依次执行：

1. 根据控球率和 Seed 决定进攻方。
2. 从适合的前场／中场位置中选择传球者和射手，并选择防守者与门将。
3. 根据“进攻能力－对方防守能力”计算强弱倍率。
4. 生成基础进球概率，叠加赛前效果，得到机会质量 `xg`（固有天赋与固定技能已退出数值模型，只做展示，不再叠加进 xg）。
5. 将 `xg` 限制在当前数值上下限内。
6. 在 `xg` 上叠加「射手射门 vs 门将扑救值」的个体 pk 判定进球；未进球再按门将优势判断扑救或射偏。

当前 Web 不区分运动战、角球、任意球或犯规阶段，也没有独立的推进成功／机会形成判定。

## 当前技能规则（只做展示）

当前杯赛的固有天赋与 5～6 星固定携带技能已退出数值模型，只做比赛过程的立绘/文案展示：

- 每名球员固定拥有的固有天赋；
- 5～6 星球员固定携带、不可替换的特殊技能。

一次射门机会最多展示一次「技能发动」。候选只来自本次机会中的射手、传球者、主要防守者和
门将。触发顺序与概率见[杯赛数值子系统：固有天赋与固定技能](20-tournament-numerical-system.md#固有天赋与固定技能)，展示不改变 xg、比分或胜负。

`skillInventory`、`skillLoadouts` 和 `skillLevels` 仍可能存在于兼容参数或旧数据契约中，
但当前模拟器不会读取它们改变结果。

当前事件保存最终 xG、触发球员、技能 ID 和来源，仅用于展示；技能不再修改 xG、也不进入
球员评分与赛事 MVP，只在总结里显示合并后的「X 次技能」触发次数。

## 结果生成、播放与存档

`simulateMatch()` 返回时，90 分钟比分、控球、射门、xG、全部事件、球员评分和 MVP 已全部
确定。页面随即调用赛事存档写入函数，然后从第一条事件开始播放：

| 事件 | 当前展示时长 |
|---|---:|
| 普通、扑救、射偏等事件 | `720 ms` |
| 进球或技能事件 | `1450 ms` |
| 终场事件 | `1050 ms` |

当前没有加速、跳过直播或直接查看结果按钮。进球与技能同时发生时，画面优先展示实际射手立绘；
其他技能事件展示技能发动者立绘。

## 球员评分与 MVP

双方 22 名首发都进入评分计算并参与本场 MVP 排序；当前赛后表格只展开我方 11 人评分，MVP
仍可能来自任意一方。评分、征程评分和结局映射见[杯赛数值子系统](20-tournament-numerical-system.md#球员评分征程评分与结局)。

## 两回合、加时与点球

16 强、八强和半决赛采用两回合总比分，不使用客场进球规则；决赛为单场。次回合总比分战平
或决赛 90 分钟战平时，比赛先暂停在可恢复的“决战准备”阶段；确认后才生成并锁定完整决胜过程：

- 加时复用常规时间的传球者、射手、防守者、门将、xG、技能与扑救逻辑，以 30 分钟事件表
  生成 5 次机会，并记录 105 分钟换边和 120 分钟结束事件。
- 加时新增比分仍相同时，进行五轮点球；提前无法追平时立即结束，相同则进入突然死亡。
- 双方 11 名首发按点球、冷静、终结和射门力量综合值排序；门将取本场实际 `GK` 槽球员。
- 每次点球由主罚者和门将详细属性进行 Seed 可复现的一对一计算，分别记录命中、扑出和射偏。
- 点球命中展示主罚球员立绘；扑出或射偏展示门将立绘。射偏文案不会错误宣称为门将扑出。
- 加时射门、xG、进球、助攻和扑救贡献合并进入本场统计与评分（技能只计入「X 次技能」展示，
  不进评分）；点球大战不计入正式比赛进球和球员评分。
- 两回合决胜直播同时显示本场比分与总比分；点球比分独立显示，不加到正式比赛比分中。

赛事结果一经记录不能从本轮检查点重试；玩家只能继续下一场或进入对应止步结局。

## 比赛模拟边界

浏览器纵切复用控球、机会、xG、技能、扑救和评分概念，但当前杯赛 Web 只运行单机
`simulateMatch()`，不包含 5v5、长期 Manager 版本的三人训练或跨阵型校准。

固定 Seed 契约位于 `data/contracts/text-match-seed-contract-v1.json`。批量报告输出场均进球、
xG、射门、胜平负、评分区间，以及分星级、分阵营、分技能、分羁绊和身价效率统计。当前
Python 参数与校准基线见文字比赛 V4 规则与校准（历史）。
