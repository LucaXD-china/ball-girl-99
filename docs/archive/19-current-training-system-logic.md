## 文档定位

本文记录 2026-08-16 技能范围调整前的训练、研习、升星、技能配置与比赛生效逻辑。
当前可运行产品只有《冠军联赛99日》杯赛；常规实时训练、每日补给与常规培养经济已经退出
运行时，其历史设计只保留在 `docs/archive/` 与旧设计文档中。

正式产品的长期养成设想仍保留在
[球员养成与技能配置系统 V2](../16-player-development-and-skill-loadout.md)，但不应当作当前杯赛规则。

## 一、运行时与存档边界

杯赛数值只写入一个键：

```text
ball-girl:tournament-save-v4:${uid}

TournamentSaveV3
  schemaVersion / updatedAt
  campaign
    campaignSeed / phase / day
    recruitment / registration
    fixtures / currentFixtureIndex / generatedOpponents
    results / outcome / roundCheckpoints
    trainedByFixture / skillStudiesByFixture / skillLevels
  squad
    collection / characterProgress
    skillInventory / skillLoadouts
  preferences
    activeMascotAnchorId（仅保留 V3 存档兼容；初赛首页忽略该值并固定 founder_left 纱夜）
```

账号、序幕和剧情档案继续使用各自存储。运行时不读取旧 `GameSave`、旧 journey 键或
`${uid}:tournament-99`；没有存档时直接建立新的 V3 杯赛存档，不执行迁移。

所有抽卡、注册、训练、研习、升星、技能配置、比赛结算和检查点恢复都会先生成完整的
`TournamentSaveV3`，再一次写回同一键。不存在先写阵容、后写赛程的半次提交。

## 二、球员范围与统一属性选择器

- 新赛事初始拥有 18 名基础球员，均为 Lv.1、0 升星阶段；杯赛不保存经验值。
- 名单锁定前，更衣室展示当前赛事收藏中的全部球员。
- 名单锁定后，更衣室、训练、阵容和比赛严格使用已注册的 18 人。
- 注册页、训练页、更衣室与比赛页都通过 `buildTournamentCharacters(...)`
  生成球员，不再各自重算属性。

赛事等级公式：

```text
level = clamp(round(level), 1, 20)
单项等级增量 = (level - 1) × 0.35
OVR 等级增量 = floor((level - 1) / 3)
```

重复卡升星阶段继续叠加在等级结果上：

```text
升星成长点 = breakthroughRank × 0.35
单项升星增量 = 升星成长点 × (0.65 + 原始属性 / 200)
OVR 升星增量 = floor(breakthroughRank / 2)
```

所有数值封顶 99。比赛模拟器接收的正是这份统一结果，因此升星不再只改变更衣室展示，
而会实际改变同一 Seed 下的球队攻防输入。

## 三、日期是唯一行动预算

存档中没有 `actionPoints`。当前操作预算始终为：

```text
剩余可用天数 = max(0, 当前比赛日 - 当前日期)
```

固定赛历：

| 比赛 | 日期 |
|---|---:|
| 16 强首回合 | Day 17 |
| 16 强次回合 | Day 31 |
| 八强首回合 | Day 48 |
| 八强次回合 | Day 62 |
| 半决赛首回合 | Day 76 |
| 半决赛次回合 | Day 90 |
| 决赛 | Day 99 |

办公室可推进 1 天或直接推进到比赛日。训练与研习都要求 `当前日期 + 3 <= 比赛日`；成功后
直接把日期增加 3。由此不会再出现“仍有日期，但另一份持久化行动点已经耗尽”的状态。

## 四、专项训练

训练中心只在 `preparation` 阶段开放。一次专项训练必须：

1. 选择 3 名不同的注册球员；
2. 三人在当前比赛的备战窗口尚未训练；
3. 操作结束日期不跨过当前比赛日。

成功后原子执行：

```text
三名球员 level = min(20, level + 2)
day = day + 3
三名球员写入 trainedByFixture[fixtureId]
```

同一球员在同一赛前窗口最多训练一次，下一场比赛前可以再次训练。只要日期允许且还有未
训练的注册球员，同一窗口可以安排多组三人训练。

杯赛没有实时倒计时训练槽、训练资金、训练笔记、每日补给或离线补结算。

## 五、技能研习与配置

各阶段开放品质：

| 当前轮次 | 开放品质 |
|---|---|
| 16 强 | 白、蓝 |
| 八强 | 白、蓝、紫 |
| 半决赛 | 白、蓝、紫、金 |
| 决赛 | 白、蓝、紫、金、彩 |

一次研习要求处于备战阶段、品质已开放、技能未达到 Lv.5，并且还有至少 3 天。成功后：

```text
day = day + 3
skillLevels[skillId] = 当前等级 + 1
skillId 写入 skillStudiesByFixture[fixtureId]
如果尚未持有该技能，则发放 1 张到 skillInventory
```

赛事初始库存中的白/蓝技能从 Lv.1 起算；未持有的高品质技能第一次研习后为 Lv.1。整届
赛事最多研习一次彩色技能。

装备规则仍由球员星级槽位数、槽位品质上限、位置兼容、技能卡空闲数量和同类别互斥共同
约束。比赛只读取首发 11 人已装备的技能。赛事技能倍率为：

```text
1 + (skillLevel - 1) × 0.15
```

Lv.1 为 1.00 倍，Lv.5 为 1.60 倍，同时作用于球队强度效果和触发时的 xG 效果。

## 六、重复卡与升星

- 首次抽到球员建立唯一可上场实体；重复卡只增加 `collection[characterId]`。
- 升星阶段范围为 0–5；每升一段消耗一张额外同名卡的可用额度。
- 判定条件为 `持有数量 - 1 > 当前升星阶段`。
- 升星不会改变基础星级、位置、技能槽数量、固有天赋或固定身价。
- 升星增量通过统一杯赛属性选择器进入更衣室、注册、训练、阵容和比赛。

## 七、检查点与重试

每轮首回合首次生成对手时建立检查点，保存：

- 完整 `squad`：收藏、等级、升星、技能库存与装备；
- 日期、当前场次索引与此前赛果长度；
- 当轮训练和技能研习记录；
- 技能等级与彩色技能研习次数。

淘汰后选择重试会从该轮检查点恢复上述全部状态，保留相同赛程、对手与 Seed，并删除本轮
产生的赛果和成长。冠军完成后重新开始则建立一份新的 Day 1 杯赛存档。

## 八、共享比赛模拟器边界

`simulateMatch` 仍是纯输入/输出：它接收已完成属性换算的双方球员、阵型、首发、技能、
准备效果和 Seed，返回赛果；它不知道杯赛阶段、页面、存档键或检查点。

确定性验证应固定 Seed，对比以下输入改变后的输出或攻防中间值：

- 球员赛事等级；
- 重复卡升星阶段；
- 技能装备与赛事技能等级；
- 进攻/防守阵型和首发 11 人。

这条边界保证杯赛业务规则不会反向污染可复用的单场模拟内核。
