# 晴空俱乐部 UI 框架 V1

## 决策状态

**已确认并接入**

项目主界面采用“晴空蓝 × 杏橙”，替代此前大面积深绿色。目标是让界面具有轻松、明亮、
有陪伴感的俱乐部气质，同时保留比赛直播、抽卡揭晓等需要戏剧张力的深色舞台。

| 语义 | 色值 | 使用范围 |
|---|---|---|
| 晴空蓝 | `#5DB7E8` | 系统识别、选中状态、主要信息进度 |
| 深空蓝 | `#347FB9` | 蓝色按钮深端、链接和可操作强调 |
| 粉雾蓝 | `#DCEFFC` | 系统背景、页签轨道、轻信息区 |
| 杏橙 | `#FF9B72` | 主要行动、提醒、情绪焦点 |
| 奶油黄 | `#FFD66B` | 奖励、资源和温暖高光 |
| 云朵白 | `#FFF9EE` | 面板、对话框和阅读底色 |
| 墨蓝 | `#25324A` | 标题和正文 |
| 成功绿 | `#4FB879` | 仅用于成功、草地与比赛语义 |

运行主题集中在 `web/src/sunny-club.css`，并在基础样式之后加载。主题层定义颜色语义、
场景表面和系统级组件外观；基础布局、动效与各玩法的专属样式仍保留在
`web/src/styles.css`。新增界面应优先复用语义变量，不再把深绿作为默认容器颜色。

## 导航层级

```text
经理办公室
  └── 全局 Dock：办公室 / 更衣室 / 训练 / 赛程 / 卡包
      └── 进入子系统
          ├── 隐藏全局 Dock
          ├── 显示本系统标题与返回按钮
          └── 使用本系统内部页签、步骤或抽屉
```

全局 Dock 只属于经理办公室。进入子系统后，玩家应专注当前任务，不同时面对全局导航
和系统内导航。每个子系统必须提供明确返回入口，内部的列表、详情和二级操作由本系统
自己的页签或步骤控制。

## 角色养成页面

参考同类角色养成界面的信息层级，但不复制具体美术、图标或深色军事风：

- 左侧或上半区保留一块稳定的大角色视觉区，优先加载透明 `standee`；资源尚未完成时
  回退到现有球员卡面，不伪造立绘。
- 右侧或下半区一次只展示一个细项：概览、养成、技能或档案。
- 角色卡墙以角色视觉为主，桌面常见宽度保持每行约 5–7 张；搜索留在紧凑工具栏，
  位置、星级、阵营和排序进入独立下拉筛选页，不长期占用卡墙高度。
- 卡牌展示区不放置遮挡卡图的身份面板，仅保留综合能力提示；姓名、阵营、位置、惯用脚
  和阵容状态统一进入档案页。收藏进度属于管理信息，不在更衣室标题区长期展示。
- 角色详情固定使用桌面侧边页签；内容仅在系统面板内部滚动。初赛阶段不提供小屏横向
  页签或压缩版信息层级。

## 表面与动效规则

- 主要面板使用云朵白到粉雾蓝的半透明表面，边缘以晴空蓝弱描边，不使用连续方块拼接。
- 杏橙用于行动和情绪高光，奶油黄用于奖励；两者不能同时占据大面积背景。
- 对话框、详情页和功能页都应有一个明确视觉锚点，其余信息围绕锚点分层展开。
- 比赛直播、技能 Cut-in 和抽卡揭晓可使用深色背景，但退出演出后回到晴空主题外壳。
- 可点击控件保留可见焦点态；颜色不能成为唯一状态提示。

## 经理办公室视觉标杆

经理办公室是“晴空俱乐部”主题的首要标杆页面。办公室背景与纱夜立绘负责沉浸感，
浮层 UI 统一采用“少女足球俱乐部手账 × 杯赛票根”语言；不再混用深色转播记分牌、
通用白色玻璃卡和彼此无关的按钮样式。

### 核心气质

- **少女感来自细节而不是大面积粉色**：使用珊瑚色缎带标签、球衣缝线、四角星芒和
  少量花形几何点缀；不堆叠爱心、蕾丝、蝴蝶结或偶像舞台装饰。
- **足球感来自赛事物件**：使用球票轮廓、球场划线、足球进度标记和奖杯终点；不使用
  暗黑电竞、金属转播台或霓虹记分牌作为常态界面。
- **统一而不抢场景**：面板保持奶油白与粉雾蓝的高明度，墨蓝承载文字，杏橙只强调
  角色署名与主要行动，确保办公室和角色仍是第一视觉层。

### 办公室组件家族

| 组件 | 标杆表现 | 必须保留 |
|---|---|---|
| 球队身份卡 | 奶油纸玻璃、球衣缝线内框、队徽后的珊瑚/绿色缎带、小型星芒 | 队徽、玩家昵称、俱乐部名、经理身份 |
| 纱夜对话框 | 同材质纸玻璃、珊瑚署名签“纱夜”、朝向角色的柔和气泡尾 | 原始引导文案、介绍流程和继续按钮 |
| 99日征程票 | 非对称票根圆角、大号 `DAY NN`、赛事阶段章、球场线、足球到奖杯的进度 | 当前天数、总天数、倒计时、阶段 |
| 行动按钮 | 主要行动为杏橙票根按钮；次要推进按钮为奶油纸玻璃和晴空蓝图标 | 原有操作、禁用态和引导高亮 |
| 全局 Dock | 同材质长条俱乐部手账；当前项使用粉雾蓝底、杏橙缝线和小星芒 | 六个入口、当前/可用/待解锁文字、焦点态 |

### 赛事阶段文案

办公室征程票只使用中文淘汰赛目标，不显示 `R16`、`QF`、`SF` 等缩写：

| 数据阶段 | 显示文案 |
|---|---|
| `day1` / `round_of_16` | `16进8` |
| `quarter_final` | `8进4` |
| `semi_final` | `半决赛` |
| `final` | `决赛` |

### 实现约束

- 主题变量和办公室组件外观放在 `web/src/sunny-club.css`；结构与定位继续由
  `web/src/styles.css` 和页面组件负责，避免在两层重复维护完整组件。
- 共享表面使用 `--club-ivory`、`--club-glass`、`--club-edge`、`--club-stitch`、
  `--club-shadow`，新增办公室浮层优先复用这些变量。
- 桌面端保留“身份卡左上、对话靠近纱夜、征程票左下、行动区右下、Dock 居中”的场景构图。
- 低于 `1280 × 720` 的窗口不挂载游戏界面，统一显示桌面尺寸提示；不维护手机横屏或竖屏布局。
- 日期推进动效仅作用于数字和足球进度标记；需要遵守系统的减少动态效果设置。

### 验收清单

- 同屏五类 UI 能被识别为同一套材质、描边、圆角和配色系统。
- “纱夜”与四个中文赛事阶段显示准确，文本没有被装饰遮挡。
- 主要操作明显高于两个日期推进操作；禁用态不能只依赖颜色表达。
- `1280 × 720`、`1440 × 900`、1080p、2K、超宽屏与 4K 均无面板互相遮挡、横向溢出或 Dock 覆盖。
- 页面仍以办公室背景和角色立绘为视觉主体，不新增全屏框架或大面积深色容器。
